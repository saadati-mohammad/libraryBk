# Competitor analysis and prioritized gap list

**Research date:** 2026-10-11. **Evidence rule:** official product documentation is cited where available. A vendor capability means only that the cited vendor documentation describes it; it is not an independent quality/performance benchmark. `Not evidenced` means the reviewed materials did not establish the feature; it does not prove the product lacks it. The comparison is capability-level, not a claim of equivalent scale, deployment or maturity.

## Executive summary

At the comparison baseline, LibraryUI/libraryBk was a focused single-library MVP: public catalog, title-level book CRUD, person records, loans/returns, reservations, ISBN metadata lookup, staff/member roles, password reset and a phone scan relay. Since then, a first persistent device registry (types, device credentials, admin lifecycle UI, audit and health fields) has been implemented. Individual copy/barcode records, policy-driven circulation, queue ordering, stocktake, staging-based imports, granular permissions/session management, registered-phone QR pairing, per-form input policies, and a production notification/security-audit pipeline remain gaps.

The strongest recurring pattern across both enterprise ILS and small-library tools is that **bibliographic title and physical item/copy are separate records**, and circulation acts on a copy barcode. Repeated operational patterns are staged imports, circulation policies, visible holds queues, history/audit/report exports, and phone/handheld scanning. The next backlog priority should therefore be data integrity and workflow recovery/security before ambitious integrations (RFID, multi-branch, MARC editing).

## Gaps and implementation choices

1. **Inventory foundation:** add explicit copies with stable local barcode, status, condition, and location, then associate each loan to one copy. This has the strongest impact on accurate scanning, returns, stocktaking and concurrent checkout. Migration must inspect legacy active loans; assigning copies to loans arbitrarily would falsify history. Until reconciliation is safe, retain legacy title-level records and report them as unallocated.
2. **Circulation and reservations:** replace constants with a small configurable rule set while defaulting to current 14 days. Define FIFO hold ordering, eligibility, expiration, renewals and overdue behavior with transparent tests. Do not add automatic monetary fines without a policy/notification decision.
3. **Scan reliability:** a hardware keyboard wedge should remain a first-class zero-install option. Phone camera pairing is a distinct authenticated PWA workflow. Introduce registered device capabilities only where they produce useful revocation/health/policy behavior; never require a proprietary scanner driver for a HID device. Batch review/undo is required before catalog commit.
4. **Auth and accountability:** session/token revocation after password reset, fail-closed attachment ownership, measured auth throttling, and actor-attributed audit events outrank cosmetic security dashboards or MFA UI. Email verification needs a configured email provider and production secret; do not silently activate a fake sender.
5. **Data import/search:** perform safe preview and row-level validation before import commits; normalize Persian ی/ک, Arabic variants and ZWNJ in search without rewriting user-visible source text. Preserve privacy-safe public projections.
6. **Catalog metadata:** no provider can guarantee “all books in the world.” Keep sources and match confidence visible; permit manual completion and duplicate review. Prioritize Iranian/persian metadata provider adapters only after access, licensing, API terms and reliability are confirmed.
7. **Architecture:** make device source adapters and circulation rules explicit interfaces/configuration, but avoid a generalized arbitrary plugin execution system. Extensibility should be typed, permissioned, audited and limited to supported providers.

## Research limitations

This is a sourced desk review, not a competitive benchmark or hands-on vendor trial. Some vendors require an account, demo, paid tier, or customer portal for precise permission, mobile, deployment and contract details. Current official technical documentation was not located for the specific Surpass, Booktracks and Innovative Sierra/Polaris matrix during this pass; cells are marked `Not evidenced`, and their features remain unverified rather than assumed absent. Iranian institutional bibliographic data requires separate due diligence for an official API, redistribution license, coverage, identifiers, and service reliability. “All books in the world” is not a guarantee any provider can credibly offer.
